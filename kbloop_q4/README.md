# 不存标签的聚焦回放（问题 4）

聚焦回放需要旧改动的标签。这轮把存储的真实目标换成网络在每个阶段开始时自己的输出。代码是 `science-of-ai-prototype-cppn` 的 `923e722`，预测 K9301～K9307 在同一提交的 `research/cppn_focus_snapshot_20261101/seed_kb.json`，运行前已推送。在 RTX 4060 上运行，走 `kb_lab.run_job`，没有调用 LLM。写于看过 K9101 和 K9104 之后，不是盲测。

## 结果

下表的比值依次是 skull、butterfly（K9305 还有 apple）。“聚焦 + 旧输出”是这轮的主角。

| Claim | 比较 | 比值 | 判定 |
|---|---|---|---|
| K9301 | 遗忘量，对聚焦 + 存储标签（≤ 1.5） | 0.52、0.80 | 成立 |
| K9302 | 遗忘量，对均匀 + 存储标签（≤ 0.6） | 0.12、0.22 | 成立 |
| K9303 | 同上，只看从未被标注的像素（≤ 0.6） | 0.18、0.25 | 成立 |
| K9304 | 遗忘量，对均匀 + 旧输出（≤ 0.6） | 0.14、0.28 | 成立 |
| K9305 | 背景漂移，对均匀 + 存储标签（≤ 2） | 1.77、2.54、3.77 | 部分成立 |
| K9306 | 学习后的误差，对聚焦 + 存储标签（≤ 1.5） | 1.01、0.93 | 成立 |
| K9307 | Picbreeder 起点，遗忘量，对均匀 + 旧输出（≤ 0.6） | 0.42、0.29 | 成立 |

- 不存标签的聚焦回放，遗忘量比存储标签的还低（比值 0.52、0.80）。这比预测的“不差太多”更好，原因没有查。一个猜测是旧输出标签不会把网络拉向它本来就有误差的真实目标，但这没有验证。
- 代价是背景漂移，增加到 1.8～3.8 倍。
- 这不等于什么都不用存：需要旧改动的位置，也需要阶段开始时的输出，也就是一份网络副本。
- apple 的遗忘量也很低，但学习后的误差仍有 0.05～0.08，受输出层陷阱影响，不能当作成功。

## 运行情况

第一次运行有 1 个实验失败（butterfly 上 PBd 的均匀 5% 存储标签），报错内容为空，原因不明，当时 GPU 上同时跑着旋钮检查。没有 claim 依赖它。

之后我重跑时犯了错：新提交给规格加了一个字段，缓存键变了，所以 24 个实验全被当作新实验重跑。我停掉了这次重跑，删除了它产生的 8 个目录，再从 `923e722` 的检出只跑缺失的那一个（见 `run.log`）。判定在补上之后没有变化，而且重跑的其余实验没有进入结果。
