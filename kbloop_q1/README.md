# CPPN 连续改动测试（问题 1）

这个实验跑在 kb-loop 的代码上，走它的 `kb_lab.run_job` 入口。代码不在这个仓库里，在 `science-of-ai-prototype` 的本地分支 `feat/cppn-continual`（commit `61a020c`）上；`patches/` 是相对上游 `68f16c9` 的两个补丁。那个分支没有推送。

## 做法

已拟合的稠密 CPPN 依次学 4 个不重叠的局部改动，每个 500 步，4 种循环顺序，回放比例 0%、5%、20%、100%。损失是当前圆盘均值加回放像素均值，权重固定。回放标签用真实累积目标，这是最乐观的情况。没有调用 LLM。

同一个预注册 commit 在两台机器上各跑一遍：`local/` 是 RTX 4060（torch 2.10），`a100/` 是 A100（torch 2.5.1）。

## 结果

| Claim | RTX 4060 | A100 |
|---|---|---|
| K9001 无回放时遗忘量 ≥ 0.3 | 部分成立（0.20、0.21） | 部分成立（0.21、0.20） |
| K9002 0% 与 100% 的差 ≥ 0.2 | 部分成立（0.19、0.21） | 部分成立（0.20、0.19） |
| K9003 5% 回放让遗忘量至少减半 | 部分成立（比值 0.87、0.88） | **证伪**（0.92、1.03） |
| K9004 apple 局部改动很难学（R ≥ 0.1） | 部分成立（0.08） | 部分成立（0.08） |

- 5% 回放没有明显降低旧改动的遗忘量，两台机器都如此。K9003 的判定不同，只因为比值落在证伪线 0.9 的两侧，这说明靠近阈值的判定经不起硬件差异。
- 区域外的背景漂移对回放很敏感：从 0% 到 5%，skull 约降 3 倍，butterfly 和 apple 约降 14 倍。**这是看到结果后才注意到的指标，没有预注册。**
- apple 的 5% 档遗忘量（约 0.14～0.17）高于 0% 档（约 0.05），曲线不单调，原因还不清楚。
- **apple 的平台来自输出层截断（事后分析，`apple_plateau.py`）**：局部改动的剩余误差停在 0.19、0.19、0.08、0.08，而网络只能输出灰色时的最佳残差算出来是 0.189、0.188、0.079、0.079。平台状态下圆盘内饱和度全部被截断，全部误差都落在这些像素上，截断处梯度为零。所以 K9004 和之前“apple 局部改动很难学”测到的主要是这个输出层陷阱，不是表示的性质。
- 所有改动都学会了（`R_after ≤ 0.3` 的比例是 100%），所以筛选和不筛选结果相同。
- 单独学习时的 F 不能预测后来的遗忘量（相关系数 -0.39～0.20，样本不独立）。

## 局限

只有 3 张图和 11 个网络，同一网络的多个改动不是独立样本。“遗忘量”只度量已学圆盘内的误差。预注册靠本地 git commit 的先后，不算外部时间证明。

运行 `python plot.py` 可重画 `report_replay_curve.png`。

## 输出层陷阱的对照（探索性，预测先提交，见 `apple_trap.py`、`st_picbreeder.py` 及对应 `.log`）

- 颜色反转把饱和度推到 0 以下，截断让梯度消失，于是卡在灰色。两个条件都需要：色相旋转或只反转亮度不会卡住，图像映射不变、只在截断处保留梯度（straight-through）也不会卡住。
- 预测 P5（保留梯度也逃不出来）被证伪，所以不能说灰色局部最优是根因。
- 保留梯度对 skull 和 butterfly 的结论影响不大，Picbreeder 的误差仍是稠密网络的数倍；apple 上影响很大，见日志。样本很少，只有两个圆盘，每张图一个 Picbreeder 网络。
